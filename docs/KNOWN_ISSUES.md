# Known issues and verification limits

Reviewed 2026-10-03. This file separates confirmed product limits from current audit findings and evidence that could not be verified. The release decision is in [GATES.md](../GATES.md).

## Confirmed product limits

- **No OS-level WorkManager job:** synchronization is coordinated by the app while it is active or resumes. The current source does not implement native WorkManager scheduling for sync after the operating system fully kills the app. Verify expected behavior on devices with background restrictions before relying on unattended delivery.
- **Backup size:** restore files over 25 MiB are rejected before file reading. Export or split larger data sets before restore.
- **External release signing:** Android release signing requires external keystore properties. Signing material is intentionally kept outside this project folder.

## Current audit and acceptance limits

- **Clean install:** the manifest and lockfile are synchronized. A fresh `npm ci --allow-remote=all` installed successfully on local Node 26.5.0/npm 12.0.2. npm 12 blocked 15 lifecycle scripts because they are not locally approved. GitHub run [37051425163](https://github.com/AmaratvKrishi-India/CRM-/actions/runs/37051425163) used Node 24.21.0/npm 11.19.0; `npm ci`, typecheck, lint, local Supabase startup, and all 348 Node tests passed before the dependency-audit gate failed.
- **Appium driver availability:** the default dependency tree no longer includes `appium-uiautomator2-driver`; its bundled dependencies caused five npm audit findings (four high, one moderate), and npm could not update them independently. The Appium CLI remains installed, while the checked-in Android UI automation uses Maestro and has no configured Appium flow. The `test:appium:drivers` command lists drivers installed separately in the local Appium home. Re-add a project-pinned UiAutomator2 driver only after a compatible stable release ships with a patched bundle.
- **Dependency audit:** full `npm audit` reports zero vulnerabilities on the current working tree. Review the GitHub status checks on [PR #1](https://github.com/AmaratvKrishi-India/CRM-/pull/1) for the exact candidate commit before merge; the earlier audit failure was against the previous lockfile.

- **Android device acceptance:** release preparation and browser-based tests do not establish current Android emulator or physical-device acceptance. A current device run remains outstanding.
- **Child-record access after reassignment:** source includes migration `20260923000017_child_read_reassignment_hardening.sql` and local RLS integration coverage. Live SQL inspection verified all five affected child-read policies in Production and Staging; linked records check current parent-lead access while preserving organization-admin access. It records no fatal app exception. Performance measurements used headless software graphics and are not representative of physical-device performance. That APK was not shown to come from this checkout.
- **Deferred Fallow review notes:** earlier audit artifacts left two candidates unresolved: lockfile-derived path handling in `scripts/generate-third-party-licenses.mjs`, and shell quoting/input trust in `scripts/process-watchdog.ts`. No exploit was confirmed in those reports; these candidates were not re-audited during this consolidation.
